02 · The solution

An autonomous agent for cloud waste

FinOps Sentinel does more than draw charts. It reads the bill, decides what is waste, explains why, and writes the command to fix it, with safety checks built in.

What it does

Upload a bill, get a fix list

  • Upload raw, anonymized billing logs (CSV) and utilization metrics
  • Works across AWS, Azure and Google Cloud
  • Finds orphaned, idle and over-provisioned resources
  • Outputs a plain-language report plus ready-to-run scripts
How it helps

Shows exactly where money leaks

  • Targets the ~30% of budget lost to unused resources
  • Replaces hours of manual spreadsheet reading
  • Ranks every leak by monthly cost
  • Example: 4 unattached EBS volumes costing $1,200/month
What's new

From insight to safe action

  • An agent that acts, not a static chart
  • Generates precise CLI scripts to archive, delete or downsize
  • Protects production before any change is made
  • One tool for multi-cloud waste hunting

Detection rules

Clear rules catch the obvious waste first. An ML layer is planned for unusual spending patterns that rules miss.

Orphaned diskattached == falseVolume or disk not connected to any machine.
Idle VMcpu_avg < 5%Machine running for 30 days with almost no work.
Oversized DBcpu < 20% and mem < 30%Database paid for at a size it never uses.
Stale snapshotage_days > 90Old backups kept long after they matter.
Unused IPtype == ip and !attachedReserved public address with nothing behind it.
05 · Safety and feasibility

Five layers between the AI and your production

The biggest risk of an agent that writes delete commands is deleting the wrong thing. Every script passes through these layers before it can run.

1

Production tags are protectedAnything tagged env=prod is flagged for review only. No script is written.

2

Rule checks validate the AIEvery command is checked against the uploaded resource list and an allowed-command list.

3

Snapshot before deleteDisks and databases are backed up first, so every change can be rolled back.

4

Dry-run by defaultScripts only print what they would do until an engineer turns dry-run off.

✓

A human approvesNothing runs until a person on the team reviews and approves it.
